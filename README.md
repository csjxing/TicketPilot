# TicketPilot · 票务助手

在 Android 手机上操作真实大麦 App 的本地票务助手。用户在手机上选择演出、场次和票档，助手读取可见页面、判断状态、执行已授权的选票操作，并记录结果。普通轮询使用本地规则、无障碍服务和内置 OCR，不调用云端模型；可选 Shizuku 作为本机输入方式。

当前开发版为 **v0.2.6-preview / code22**，新增文件中转站远程诊断，并修复内容事件噪声导致的部分读取暂停；601 项 Android 测试、Lint 和构建通过，发布和真实链路验收待完成。已发布历史包见 [v0.2.5 APK 和源码](https://github.com/csjxing/TicketPilot/releases/tag/v0.2.5-preview)。手机最后核实为 v0.2.3，真机操作和跟进按用户要求保持暂停。**自动提交订单和锁票尚未开放；USB 物理拔线后的完整流程仍待验收。付款由用户完成。**

日常主入口为“计划 / 领航员 / 我的”。从真实大麦内的悬浮助手读取当前场次和票档，用户选择价格与张数后保存计划。领航员提示当前步骤与下一步，权限、模型、远程诊断、云端协作高级设置与交接资料位于“我的”。

“我的 → 远程诊断”先预览版本、权限与最近最多 63 条固定状态码，再交给已登录的“远见中转”App 发送，无需重复配置 Key；必须在远见中转中点发送，交接不等于收到回执。也可选填 HTTPS 管理 Key，直接在票务助手内上传，并核实附件 `ready` 回执。不发送原始日志、截图、页面正文、实名、Key 或订单；共享不启动抢票、不开放云端任意控制。电脑从同一个[文件中转站](https://foresight.weisee.com/relay)取得诊断全文，说明见 [cloud/relay.md](cloud/relay.md)。旧“云端协作”高级接收器仍保留，尚未部署。

读取时，只有同一窗口中整个 OCR 裁剪区像素与原生事实均未变化，才可把内容事件当作噪声复核；仍保留原 3 秒时效和点击门禁。真实画面、库存或选择变化会重新读取，恢复预算耗尽后仍会暂停。此项需要真机验证，不能承诺消除全部“页面持续变化”提示。

## 当前能力

| 功能 | 当前状态 |
| --- | --- |
| 从真实大麦搜索、读取演出、场次和票档，由用户选择 | 已在测试 vivo 和指定演出验证；其他页面需重新适配 |
| 本地读取、OCR、动态检查节奏和状态日志 | 已实现；正常轮询不需要模型 |
| 可选 AI 辅助 | 手动配置接口后，预览并发送配置、场次、票档或异常问题；当前已保存配置；新版真实调用与交互待验收 |
| 本机学习笔记 | 人工确认后保存供后续分析参考，不自动变成点击或下单规则 |
| `ALERT` 仅提醒 | 发现符合条件的页面信号后暂停 |
| `PREPARE` 准备购买 | 已在 USB 连接时自动选票并进入已加载的确认购买页，然后暂停 |
| 自动提交、待付款订单核验和锁票 | 未开放，生产订单页适配名单为空 |
| 实际拔掉 USB 后完整运行 | 待验收，不能用接线测试代替 |
| 内置知识库、源码导出、另一台电脑接手 | 已实现；源码包不含账号、签名密钥和设备授权 |
| 文件中转站远程诊断 | v0.2.6 已加入分享与可选直连；整包通过，手机发送及电脑读回待验收 |
| 手机下载更新与高级私有诊断同步 | 历史发布及电脑下载哈希有证据；手机内更新待验收，旧接收器未部署 |

支持 **1–2 张计划配置**；真实数量加号尚未适配，不能把两张配置认定为已自动选中两张。有票信号、可选票档和确认购买页都不等于已经锁票。现有 PREPARE 证据来自 vivo X300 Ultra / Android 16、大麦 9.0.37；大麦升级、不同手机或演出页面需要重新验证。详细结果见 [Android 验收记录](android-app/VALIDATION.md)。

## 可选 AI 辅助

在“我的 → 管理模型”填写 HTTPS 接口地址、模型名和 API Key，兼容 Chat Completions 接口。功能默认关闭；打开页面、保存设置和普通监控均不会自动请求模型。每次发送前展示本次问题、经过筛选和遮盖的上下文，以及接收方。首次使用可先测试连接。此后从需求、场次、票价、检查速度或暂停提示旁直接进入 AI 帮助，问题和公开参考信息会自动带入；点击“发送给 AI”才调用模型，完整正文在同页展开，不再先选问题类型或阅读长弹窗。

模型可把自然语言需求整理为待核对的目标草稿，由你检查后明确保存；保存后可在“我的 → 更多设置 → 手动修改目标”中调整。草稿保持暂停，并要求回真实大麦重新选择核对；模型不会直接启动监控、点击页面或提交订单。读取的摘要标明时间，旧摘要和模型推测不能作为实时库存证据。你可以编辑并确认保存本机经验笔记，后续主动发送时再作为未验证参考；这些笔记不训练模型权重，也不更新适配器。

API Key 用 Android Keystore 加密保存，不进入日志、知识库或导出包。请求不附带截图、完整控件树、实名和订单正文；已知敏感值及常见号码会遮盖，但自由输入仍需在发送前自行核对。AI 请求只发送给你选定的服务，费用和数据保留由该服务决定。每日调用次数与单次输出由用户配置，可选择本机不限次数、输出使用服务商默认；连接测试也计数，请求失败不自动重试。`store: false` 不代表第三方服务保证不保留数据。

- [另一台电脑接手](android-app/handoff/START_HERE.md)：环境检查、构建、签名和调试。
- [开发协作说明](android-app/AGENTS.md)：先读此文件，再修改 Android 工程或操作手机。
- [手机独立运行审计](android-app/handoff/STANDALONE_AUDIT.md)：本机运行边界和待完成测试。
- [内置知识库](android-app/app/src/main/assets/knowledge/)：随安装包提供的离线说明。

```sh
git clone https://github.com/csjxing/TicketPilot.git
cd TicketPilot/android-app
python3 handoff/doctor.py --offline
```

`doctor.py` 只检查环境，不下载、安装、点击或启动监控。构建需要 **JDK 17、Android SDK Platform 35**；设置 `ANDROID_HOME`，或在 `android-app/local.properties` 指定本机 `sdk.dir`。项目包含 Gradle Wrapper，首次构建需要下载依赖。

```sh
# 在 android-app 目录执行
sh ./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
python3 -m unittest discover -s handoff -p "test_doctor.py"
```

Windows 使用 `gradlew.bat` 和 `py -3`。APK 输出为 `android-app/app/build/outputs/apk/debug/app-debug.apk`。安装与系统授权由用户正常完成；新电脑生成的调试签名可能不同，不能通过卸载或清数据来绕过覆盖安装冲突。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `android-app/` | 当前 Android 应用、测试、离线知识和电脑交接工具 |
| `damai/`、`tests/` | Python 离线状态机、模拟订单防重与测试 |

早期电脑脚本含历史演出日期、固定屏幕布局和本机工具路径，**不能直接当作通用抢票入口运行**，也不是 Android App 的运行依赖。它的真实提交与待付款流程尚未端到端验收，见 [历史脚本说明](scripts/PHONE_WATCH.md)。

离线演练不连接手机、不创建真实订单：

```sh
# 在仓库根目录执行
python3 -m damai --demo
python3 -m unittest discover -s tests
```

## 数据与提交边界

源码默认不包含实际演出配置、观演人资料、账号、设备序列号或登录凭据。真实配置、截图、设备日志、订单记录、构建缓存和导出包仅留在本地忽略路径；签名材料另行安全保存。从 v0.1.11 起，App 声明网络权限，用于用户主动启用并发送的 HTTPS 模型请求。普通监控、OCR 和离线指南继续在本机执行；大麦 App 仍需联网。

验证码、登录、权限请求、未知页面及平台阻塞由用户处理。程序不提供验证绕过、私有库存接口或支付操作。恢复、导入和升级不能清除订单防重复记录，也不应自动沿用历史购买授权。
