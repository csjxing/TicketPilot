# 票务助手工程交接

## 当前目的

继续维护同一台 vivo 上运行的 Android 票务助手，让用户日常在手机完成操作。导出工程用于换另一台电脑后由 Codex 或其他开发工具接着改进；不是要求迁移到另一台手机，也不是在手机执行源码。

开始先读 `handoff/START_HERE.md`、`README.md`、`VALIDATION.md`。用 Python 3.9+ 运行 `handoff/doctor.py --offline` 检查电脑；需要联调时，重新核对目标 vivo 的连接、解锁和应用版本。doctor 只读，不安装、不启动应用、不点击、不下单、不解锁、不清数据，也不代替端到端验收。

## 工作方式

- 复用当前工作区，先看现有改动；不要覆盖未提交工作、清数据或因接手而自动重建环境。
- 保持代码、本地规则和手机运行边界清楚：普通监控使用本机 Java、无障碍与内置 OCR，不调用云端模型。Shizuku 仅在用户正常启动、授权并连接后使用。
- 手机由一个操作者控制。并行代理可修改互不冲突的文件或审查，不同时对手机点击、安装、切换页面或读取实时界面。
- 每次真机运行前，重新核对演出、城市、完整日期时间、票价、数量、预算和模式。历史谢霆锋测试场次、过期孙燕姿任务都不是当前购买授权，不自动沿用旧观演人绑定。
- 用户当前明确授权优先于本文件。界面测试默认停在最终提交前；开发自动锁单功能与实际创建订单的授权是两件事。不要把一次调试启动或导入配置当作购票授权。
- 遇到登录、验证码、锁屏或无法核实的状态时，保留具体原因并交接；不绕过系统或平台验证，不猜页面、不用未核实坐标兜底下单。

## 已知验收边界

以 `VALIDATION.md` 最新章节为准。2026-10-25 的有效证据包括：v0.1.8 在 USB 连接时由助手前台启动并自动试选，核实目标后进入已加载的确认购买页，随后暂停；v0.1.9 的导航、知识搜索、文件导出和导入预览等 UI 路径通过本机测试。

自动锁单仍未开放：`OrderCheckoutAdapter` 的生产适配名单为空，不能通过删除门禁或注册合成 fixture 宣称完成。真实提交控件、观演人、金额、协议和待付款页面仍需逐项适配。USB 物理断开后的运行仍未验收，见 `handoff/STANDALONE_AUDIT.md`。构建、Lint、输入回调、可见票价和手工点击都不能替代端到端证据。

## 数据与订单记录

- 姓名、证件、账号、cookie、授权 token、签名密钥、原始截图或偏好设置不写进公开交接、日志、知识库或源码包。诊断仅保留公开版本、结构、状态和脱敏结论。
- `OrderAttemptStore` 的 `order-attempt.journal` 是本机持久提交屏障。配置修改、导入、升级、重连或未知结果都不能删除它或自动再次提交。对旧订单或结果不明的页面只提示核查，不能认定本次成功锁票。
- 保存配置保持未启动；恢复草稿保持 `armed=false` 并要求重新从真实大麦核对。系统权限、设备输入连接和购买授权不能从文件导入恢复。
- 新电脑签名可能不同。遇到覆盖安装签名不匹配，禁止卸载重装或清数据绕过。原签名需用户另行安全迁移，不将密钥打入电脑交接包。

## 验证与交付

- 项目要求 Java 17；SDK、Gradle Wrapper、插件版本从工程配置读取，不硬编码旧电脑路径。
- 运行与改动相关的单元测试、Lint 和构建。完整本地命令：macOS/Linux `sh ./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`；Windows `gradlew.bat --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`。
- doctor 测试为 `python3 -m unittest discover -s handoff -p "test_doctor.py"`（Windows 可用 `py -3`）。这些测试使用模拟输出，不连接手机。
- 真机验证明确区分人工导航、助手自动动作、提交结果与付款状态；记录当前构建版本、通过项和未验证项，不以测试数量代替真实结果。
- 临时调整亮屏、旋转等设备设置前记录原值，结束恢复并读回。不要留下未授权的持续任务或默默恢复旧监控。
- 更新源码交接包时保留 `AGENTS.md`、`handoff/`、构建脚本、源码和知识资产，排除本机环境、缓存、私有运行证据、APK 构建输出和签名材料。
