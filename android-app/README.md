# TicketPilot · 票务助手 Android · v0.1.11 体验版

## v0.1.11：可选 AI 辅助

“任务”和“设置”提供“AI 辅助”入口，用于配置建议、场次比较、票档解释与异常分析。该入口默认不启用模型，也不自动调用；它提供建议，也可把自然语言整理成待核对目标草稿（保存后可在设置中调整）；必须由用户检查并确认保存，保存后保持暂停、等待真实大麦目录重新核对，不能直接点击大麦或提交订单。打开 AI 辅助前暂停当前监控，返回后仍由用户主动开始。

在页面内配置 HTTPS 接口地址、模型名、API Key、单次输出上限和每日调用次数。当前使用 OpenAI 兼容的 Chat Completions 协议；兼容服务如不支持 `max_completion_tokens`，可切换传统 `max_tokens` 输出上限参数。接口能力和可用模型以实际服务为准，不预置账户、密钥或“免费”承诺。

先保存配置，再主动测试连接。分析时选择问题类型，填写问题并查看发送预览：预览包含最终问题、公开目标与目录、最近一次读取的有限状态摘要，以及接收服务；确认后才发送同一份内容。摘要带读取时间，不能当作刷新后的库存。不会发送原始截图、完整控件树、账号、实名匹配信息或订单正文。程序遮盖已知敏感值及常见标识，用户仍需检查自由输入，不在问题里填写密钥或完整证件。

“读取大麦当前页”会等待用户在短时间内切回大麦，再做一次本机读取，必要时使用本机 OCR。它只保留允许的日期、时间、价格、状态等摘要；账号、订单、验证码页面只提供类别。读取后仍需回到 AI 页预览并主动发送。该按钮不点击票档，也不是被动收集所有页面。

模型输出以普通文字展示，不能执行代码、链接或操作指令。可以编辑后主动保存为本机经验笔记，供以后的手动分析参考；笔记会标为未验证，不改变页面适配、库存判断或下单规则。它不是模型权重训练，也不会因一次模型回答就“学会”新版大麦。

API Key 与接口配置使用 Android Keystore 加密，保存在不参与系统备份的本地文件，不写入普通偏好、通知、日志、交接 ZIP 或 APK。更换接收地址需重新核对密钥。设置页可关闭调用和清除配置；学习笔记另有清除入口。模型调用使用正常 HTTPS 校验，不跟随重定向，不自动重试；取消或离开页面会取消当前请求。连接测试也计入每日次数，失败可能仍产生服务方费用。`store: false` 请求标记不保证第三方服务不保留数据。

本版增加 INTERNET 权限。AI 模块只在用户主动启用并发送时请求模型。普通检查、OCR、离线指南和购票规则不依赖云端模型。**自动锁单仍未开放，物理拔线后的完整选票仍待验收；真实模型接口需用户自行配置后另行验证。**代码、构建、安装、接口连通与有效建议分别验收，最新结果见 [VALIDATION.md](VALIDATION.md)。

实现依据：[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Android Keystore](https://developer.android.com/privacy-and-security/keystore)。

## 本台手机独立使用，另一台电脑接手开发

主要目标是当前这台 vivo 继续运行助手。读取、OCR、规则决策和标准点击在手机执行，电脑用于开发和排查。**USB 物理拔线后的完整选票仍待验收，自动锁单入口仍未开放**；代码在手机执行不等于这两项已经通过。

日常入口是“任务”和“设置”。“使用与维护 → 查看单机使用步骤”说明手机启动、Shizuku 重启恢复和暂停处理；不需要向手机重新导入配置才能换电脑。

换电脑时，在“使用与维护 → 电脑接手与备份”导出**电脑交接包（ZIP）**。解压一次就是完整 Android 工程：根目录 `AGENTS.md`、`handoff/START_HERE.md`、只读 `handoff/doctor.py`、源码、测试和8篇知识都在其中。用 Codex 等工具打开该文件夹，按接手说明继续。页面也可复制一段不含私人信息的接手说明。只读检查不自动安装、点击、启动监控或下单。

开发环境、缓存和签名密钥不在包里。新电脑构建的默认调试签名可能不同，覆盖安装前核对证书；不要通过卸载或清除数据来解决签名冲突。原有目标和提交记录应保留。需要同签名更新时，由持有者单独安全配置签名，不能把私钥放进交接包。

“导出资料与目标备份”和“选择备份并预览”保留为次要恢复工具；它们不是换电脑接手的必要步骤。该备份 ZIP 才含嵌套 `handoff/source.zip`；主电脑交接 ZIP 无需二次解压。

## v0.1.9 交互与离线资料基础

这一版把常用操作分为底部三个入口：**任务、设置、帮助与换机**。任务页根据当前状态只给一个主要下一步；首次先完成必要设置，之后选择演出、核对场次与票价，再开始监控。日期、时间与停止时间可以点选，不必输入带时区的时间字符串。自动锁单目前仍未开放，不能把交互更新理解为下单验收完成。

“帮助与换机”内置 8 篇离线说明，可按关键词搜索：快速开始、权限、选演出、监控状态、故障处理、换机、当前能力和开发交接。知识库不调用模型，不依赖联网，不包含本机账号、实名、订单或原始截图。源码快照也随 APK 携带，可从换机包导出后用相应工具查看；App 不包含源码编辑器或编译器。

换机时在旧手机依次**导出换机包（ZIP）**和**导出当前安装包（APK）**。新手机安装后，在同一入口选择换机包、查看预览，再保存为待核对草稿。公开目标、票价与检查节奏可以带走；权限、登录、观演人匹配信息和运行授权需要重新设置。必须从真实大麦重新选择演出核对后才能开始。导入不会清除本机已有订单提交记录，也不会自动运行、提交订单或付款。没有有效目标时也能导出知识与开发资料。

迁移包有版本、文件清单与 SHA-256 损坏校验，按白名单限制文件名、数量、大小与配置字段；不解压到任意路径，不安装或执行导入源码。损坏校验不等于可信数字签名。未知模式、未来 schema 或额外敏感字段会被拒绝。`LOCK_ORDER` 导入后降为 PREPARE，并需重新核对。

v0.1.9 已安装到 vivo，并通过首页状态引导、设置连接、开始提示取消、离线知识搜索与返回、系统文件选择器 ZIP 导出、正常导入预览及取消、纯资料包预览、损坏包拒绝和 APK 导出测试。取消后原目标与设置保持不变，APK 导出内容与安装版本一致，全程未启动监控。构建为 316 项单元测试通过，Lint 0 错误、9 条警告。尚未执行导入应用或跨手机迁移，大字体也未完成真机验收。此前 v0.1.8 的选票测试结论如下。

在 Android 手机本地运行，操作手机中已经安装的**真实大麦 App**。日常配置、启动、暂停和导出记录设计为在手机上完成；USB 物理断开后的运行尚待本轮验证。

### v0.1.8 离线代码进展

- 订单页解析按精确大麦版本名与版本号、原生控件 ID、祖先区域和完整标签匹配。完整标题、日期时间、单价、数量、小计、应付、额外费用和观演人均独立读取，不用配置补缺字段。生产名单为空，合成控件 ID 只存在于测试。
- 观演人以完整姓名及用户选填的可见尾号匹配。唯一未选目标可提出一次勾选；点击前重读完整页面，并在最终找到的实际控件所属行再次核对姓名和尾号。点击后重新读取已选状态；同名无法区分、多选、选错人、隐藏或受保护字段均暂停。未接受协议或提交按钮未启用时不提交。
- 原生读取比较两次树快照，检查窗口和页面代次；树截断、变化或超时不作可靠证据。读取预算是合作式的，无法中断单个 Android Binder 调用；最终派发还有独立期限。性能和真实触控效果仍待实测。
- 只有写入提交许可还不算已提交。重启后从持久日志恢复是否消费过许可；匹配的历史订单、缺少官方创建时间的待付款页，均只提示人工核查。只有本次已消费提交许可、订单目标完全一致且官方创建时间能证明本次归属，才报告新订单成功。未知结果保留提交屏障。

后续真机复测修复了保存配置时重复取消空闲 Shizuku 连接、导致前台启动自行拒绝的问题。页面明确提示排队拥挤或原生错误时优先暂停；只有“确认购买”标题而无订单操作内容时记未知，不把错误页当作准备完成。该阶段构建 277 项单元测试通过，Lint 0 错误、9 条警告。真实页面已取脱敏结构：提交标签实际为无原生 ID 的“立即提交”，多项订单字段也没有 ID，不能直接套用当前合成页面解析器。详细证据和未完成项见 [VALIDATION.md](VALIDATION.md)。

2026-10-25，在 vivo X300 Ultra（V2547A，Android 16 / API 36）与大麦 9.0.37 上，**v0.1.5 的 Shizuku 路径在 USB 保持连接时三次通过 PREPARE：从未选票档开始，自动试选、核验 980 元／1 张／总价 980 元，进入“确认购买”页后自动停止**。其中前两次从调试入口启动，第三次从 vivo 系统通知的真实“开始”按钮启动。测试目标为谢霆锋杭州 2026-11-15 19:00。未提交订单或付款，不能确认锁票。

## 这一版能做什么

- 读取大麦前台页面的无障碍控件；必要时使用随安装包附带的中文 OCR 在手机本地识别。
- 按自设演出关键词、城市、日期、时间、票价及预算判断；已实现返回详情、打开票档和选择可见票档的操作路径，实际动作效果仍需逐项验收。
- 使用票档专用适配器，将自绘日期和价格文字映射到可见节点容器；以同帧橙色文字及完整边框核验选择状态，数量和金额还需节点与 OCR 一致。
- 在用户设置的区间内动态安排操作间隔，普通轮询不调用模型。
- `仅提醒 / ALERT`：发现符合条件的有票信号后暂停并通知。
- `准备购买 / PREPARE`：在可核实的条件满足时，尝试选票并进入**确认购买页**，随后暂停提醒。**最终提交订单、实名核对及付款由用户手动完成**。
- PREPARE 中新增 `PROBE_TIER`：已核实目标场次、目标档未明确缺货但库存尚不明时，进行普通试选并读取后续反馈。试选记录为 `PROBING`，不会因此声称有票、锁票或订单成功。ALERT 不自动试选。
- 保存有票、缺货、未知、阻塞和操作结果，支持在手机上导出 JSONL。
- v0.1.4 增加目标节点刷新、活动窗口和显示屏核对，以及支持系统上的敏感控件检查；操作结果未知时暂停，保留具体原因。
- v0.1.5 增加可选 Shizuku 本地调试输入，页面读取仍使用无障碍与本地 OCR。默认继续使用无障碍触控；只有用户明确切换、授权并连接后才可准备该方式的监控。连接或操作失败不会自动切换另一种点击方式。
- v0.1.6 准备时清除助手的旧结果提醒，将通知动作改为“开始监控”，并增加启动接收、忽略、拒绝和异常记录。点击通知正文仍只打开助手，不会启动；真机已确认只保留准备通知且“开始监控”按钮可见，实际启动日志仍待验收。
- v0.1.7 新增“搜索并选择演出”：从真实大麦当前可见页面读取项目、场次和票档，在助手中核对并应用目标；高级手动填写仍保留且默认折叠。谢霆锋杭州的完整配置流程已通过；详情页手动点一次“立即预订”，检测到票档页后继续读取。多演出、多票价同时选择等场景仍需分别验证。

本版只支持 **1 张**。初始配置为空，不包含先前演出、观演人或账号；大麦账号由用户在官方 App 登录。

## 升级兼容性

当前适配依赖本次读取验证所用的大麦页面布局、控件资源 ID（`resource id`）及橙色选中状态。大麦升级或页面调整可能使识别失效，本版不保证跨版本兼容。无法核实的状态会记为“未知”，连续读取仍无法确认时暂停，避免按猜测继续操作。

页面适配与购票决策已经分离，后续可单独更新适配器。**大麦版本及页面特征匹配、使用真实页面样本进行升级回归，仍是下一步工作，当前尚未实现。**升级后需重新完成目标页面的真机验证。

## 首次使用

要求 Android 11 / API 30 或以上。工程目标 API 为 35；目前已联调 vivo X300 Ultra / V2547A 的 Android 16 / API 36。其他系统版本和不同大麦页面尚不能据此视为已兼容。

1. 安装构建出的 APK；如系统要求，按系统流程允许安装该来源的应用。
2. 在官方大麦 App 登录，回到助手。
3. 在“设置”页点击“设置页面读取”，阅读用途说明。在这台 vivo 的系统无障碍页面向下找到“已下载的服务”，进入“票务助手 · 界面读取”，开启详情页顶部的同名服务开关。下方“票务助手 · 界面读取快捷方式”和 TalkBack 均无需开启。其他系统菜单可能不同；如系统提示受限设置，由用户按系统授权流程处理。
4. 点击“允许通知”，允许通知，并确认“有票及需要处理”通知类别可用；如选用 Shizuku，按下节主动授权并连接。
5. 在“任务”页点击“选择演出”或“选择 / 更换演出”，输入关键词并点“去大麦搜索”，在真实大麦搜索后，点击“票务助手 · 演出选择”通知回到助手选择项目。到项目详情时按提示手动点一次“立即预订”；助手读取票档页后，再通过通知回到助手选择场次和接受票价，核对并应用目标。也可展开“手动修改目标”，自行填写，再点“保存修改”。
6. 先在真实大麦打开目标演出的票档页面，回到助手“任务”页，根据主要按钮完成缺少的设置。
7. 点击“开始监控”（有未保存修改时显示“保存并开始”），在提示中确认票档页已打开，再在 20 秒内通过最近任务切回那个大麦页面。当前页面可见后才继续扫描；不会重新打开大麦首页。

**运行时保持手机解锁、屏幕点亮、大麦在前台。**此版本不会自动解锁，也不承诺锁屏、切换应用或系统回收服务后继续运行。需要调整亮屏时长时，由用户在系统设置中设置。

## 从真实大麦选择目标（v0.1.7）

1. 在“任务”页点击“选择演出”或“选择 / 更换演出”，输入演出名称，可附带城市，如“谢霆锋 杭州”或“谢霆锋杭州演唱会”，再点“去大麦搜索”。助手会切换到真实大麦，通过正常可见控件搜索。读取完成后点击“票务助手 · 演出选择”通知打开结果；这台 vivo 会阻止后台自动打开助手，不能等待它必然自动返回。
2. 从当前可见结果选择项目。助手会用真实无障碍节点核实详情身份，然后通过提示及通知请你在真实大麦手动点一次“立即预订”。现版不对这个缺少可用节点的按钮执行 OCR 坐标点击。提示后会留出至少 30 秒供你操作，整步最多 45 秒；检测到票档页后继续读取；超时可重新使用“我已打开演出，读取当前页”。读取完成后通过通知回助手选择场次日期和时间。这里只呈现本次可见内容，不表示搜索结果或场次已经全部读取；未显示的项目或场次需先在大麦页面展开或滚动，再重新读取。
3. 勾选一个或多个接受票价，点击“下一步：核对并保存”。确认页列出真实项目标题、识别关键词、城市、完整日期和时间、接受票价、1 张及最高票款。缺少城市、完整年份／日期／时间、有效票价，或场次已经过去时，不能应用；不会猜年份或用隐藏接口补全。
4. 在确认页点击“保存到任务”，只保存目标并保持 `armed=false`，数量为 1 张，预算取所选最高票价，停止时间默认为所选场次开演时间（北京时间）。其他节奏和模式设置保留，后续可在“手动修改目标”中修改。应用或选择任何项目都不会自动开始监控或提交订单。

也可先在大麦打开目标页，再使用“我已打开演出，读取当前页”。该操作不重新打开大麦首页；选择页退出后，需回到真实大麦，助手等待大麦前台后读取。如果底下仍是助手主页，请手动切回大麦；超时或遇到锁屏、验证码等状态会停止。票价可见、按钮可点或“售票中”不代表有票；显示的库存仅是当次页面信号，不是锁票证明。

用于后续识别的关键词从搜索内容自动提取：排除所选城市、纯日期及票务通用词，再选取实际标题中能准确命中的最长名称片段。例如“谢霆锋杭州演唱会”会提取标题原文“谢霆锋”，不要求整句搜索内容出现在标题里。确认页会显示提取后的关键词；没有真实匹配时不猜艺人别名或纠正错字。完整标题另外展示，避免把长标题直接作为票档页的识别条件。

Shizuku 需要在手机上保持运行，重启手机后可能需要重新启动。页面读取仍需“票务助手 · 界面读取”无障碍服务；当前目标、1 张限制以及 PREPARE 停在确认页的规则不变。连接断开、输入结果未知或无法核实目标时暂停，不自动重试该输入。暂停会阻止后续动作并尝试取消在途操作；已经派发的触摸无法保证撤回。用户已批准安装及继续测试；官方 Shizuku v13.6.0 已安装，并按 App 显示的官方命令通过 USB 启动，界面显示正在运行（adb）。用户已在权限弹窗选择“始终允许”；主动点击连接后，助手显示“Shizuku 已连接；点击结果仍需页面验证”。此后 v0.1.5 已完成三次 USB 连接状态下的真实 PREPARE 测试，均自动选票并进入确认购买页后停止。USB 断开两次测试均未记录到启动；第二次已定位到 shizuku_server 发起的强行停止和准备通知取消，早于首次观察到 USB 不可用，但与实际拔线的先后未定；具体触发分支仍待排查，不能据此认定断线输入失效。

## 配置说明

| 配置 | 填写方式 |
|---|---|
| 演出关键词、城市 | 使用目标页面实际可见的名称；避免过于宽泛的关键词 |
| 演出日期、开演时间 | `YYYY-MM-DD`、`HH:mm`，如 `2026-12-31`、`19:30` |
| 接受票价 | 逗号分隔的完整票价，如 `980,1380,1680`；这是格式示例，不是默认授权 |
| 张数 | 本版固定支持 `1`，其他数量会被拒绝 |
| 票款上限 | 正整数元，不能低于任一接受票价对应的票款 |
| 停止时间 | 含时区的完整时间，如 `2026-12-31T19:30:00+08:00`，必须晚于当前时间 |
| 最短／最长间隔 | 整数秒，最短 3 秒，最长不超过 10 分钟，最大值不小于最小值 |
| 发现有票后 | 仅提醒，或准备购买至确认页 |
| 点击方式 | 默认无障碍触控；实验 Shizuku 方式需另行主动授权及连接，切换会暂停任务 |

配置中的间隔用于控制界面操作节奏，页面加载、状态观察和 OCR 也需要时间，不能据此保证固定频率或响应时延。在运行中保存新配置会先暂停任务，保存后需重新开始。

## 异常和提醒

- 验证码、登录、网络异常、锁屏、离开大麦或页面不匹配：暂停，交由用户处理。
- 连续无法确认页面或库存时：记为“未知”并暂停，不把失败当成缺货。
- 进入订单相关页面：停止自动操作，请用户核对；不声称已经生成待付款订单。
- 所有有票提醒都表示**页面信号**，不是锁票证明。2026-10-24 对大麦 9.0.37 做了 UID 流量对照：同页点票档 10 次中 5 次在随后 5 秒收发为零，返回重入 3 次均有明显通信。不能把点票档视为每次刷新；这些流量未验证库存接口或服务端缓存，详见验收记录。

开始监控前要求通知权限已开启。但通知类别关闭、勿扰模式、静音、系统电量策略和服务被系统终止，都可能影响提醒。开启通知本身不能保证一定响铃；使用前需要在目标手机验证通知和暂停入口。本次联调已看到系统通知记录 `seen=true`，但声音、振动以及通知中的暂停动作还未完成验收。当前没有 Dot、短信、其他手机推送或云端模型接管。

## 权限与隐私

- 需要用户主动授予无障碍服务和通知权限；无障碍能力用于用户主动搜索、选择目标、读取当前页，以及手动启动监控后的大麦前台界面读取与可见操作。
- 默认方式不需要 root、ADB 常驻、后台服务器或账号密钥；可选 Shizuku 方式需要用户启动的本机调试服务运行。普通监控不使用网络模型，OCR 模型随包提供；v0.1.11 的 AI 网络请求由用户手动发起，大麦 App 自身仍需联网。
- OCR 截图只在内存中处理，不保存、不上传。读取内容不会作为完整屏幕文本写入日志。
- 内置 OCR 使用 ML Kit；其[官方数据说明](https://developers.google.com/ml-kit/android-data-disclosure)披露 SDK 会收集设备、应用及性能等诊断数据。当前尚未针对本工程依赖版本验收联网后的诊断行为，不能把“AI 关闭”表述为整个 App 保证零联网。此事项与 OCR 截图、本次模型请求的内容边界分别核对。
- 配置保存在应用私有存储中；检查记录保存时间、通用状态／原因、耗时、读取来源及节点数量；诊断记录还包含操作类型、目标范围和点击路径，不保存截图、证件资料、观演人或订单正文。应用备份已关闭。
- 日志有界保留：约 2,000 条，达到 2,200 条或文件大小阈值后裁剪旧记录。导出由用户通过系统文件选择器决定位置；导出的文件不再受应用私有存储保护。
- 本版无验证码破解、设备伪装、风控绕过、私人库存接口或支付操作。遇到保护和不支持的页面会停止。

## 后续开发顺序

1. 在已通过的谢霆锋杭州单票价配置流程基础上，验证其他演出、多个票价同时选择、缺字段、项目身份变化、超时及不同返回场景；不将一次成功外推为全部兼容。
2. 查明第二次断线测试期间 shizuku_server 发起 force-stop 的具体分支，排除该影响后重新验证真实通知启动与断线 PREPARE。v0.1.5 的真实通知启动已通过；声音、振动和暂停行为仍需补齐，默认无障碍失败仍未解决。
3. 增加大麦版本及页面结构兼容检查，并用真实页面样本回归；用真机数据测量每步耗时和页面变化。
4. 后续若实现单次提交至待付款，需要当前任务明确授权：观演人、场次、票档、数量和总价逐项核实，已有待付款订单时禁止重复提交，支付交给用户。

这些是后续里程碑，不是本版已完成的功能。首次安装无需保持电脑连接；真机联调阶段可临时连接电脑以便核查问题。

联调可临时通过电脑采集页面证据，与 App 本身仅在内存处理截图的行为不同。联调时如手机锁屏，需用户再次解锁；临时设置的交流供电保持亮屏应在测试结束后恢复原值，恢复结果由最终验收记录确认。
