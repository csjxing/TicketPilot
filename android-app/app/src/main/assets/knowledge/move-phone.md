# 本机独立使用，换电脑继续开发

## 手机继续用，电脑可以换

主要目标是让当前这台 vivo 完成日常设置、选择演出、开始、暂停和查看提醒。换电脑只是换开发与排查工具，不需要把手机配置搬到另一台手机，也不需要在这台手机重新导入配置。

页面读取、文字识别、规则判断与点击在手机上执行。当前真实选票测试是在 USB 连接状态下完成的，物理拔线后的完整运行仍未验收；不能把“代码在本机执行”当成已经验证离开电脑稳定可用。

## 这台手机的日常路径

1. 在手机确认 Shizuku 正在运行；重启后需要按官方无线调试流程重新启动，详见“权限、连接和手机重启”。
2. 在助手“设置”页检查页面读取与通知。使用兼容触控时，允许票务助手使用 Shizuku，再点“③ 连接点击服务”。连接就绪不等于监控已经开始。
3. 回“任务”页，从真实大麦选择演出、场次与接受票价，核对 1 张和预算。
4. 打开大麦的目标票档页，回助手点“开始监控”，按提示切回该页面，保持解锁和亮屏。
5. 遇到排队、验证码、登录或页面异常时先在手机处理，再主动开始。到确认页后仍需你提交订单；自动锁单尚未开放。

手机重启和服务被系统停止时，权限或输入服务可能需要重新检查。助手不会自动解锁，也不会在连接恢复后自动开始。

## 换一台电脑，让 Codex 接手

在“帮助”里打开“电脑接手与备份”，点击“导出电脑交接包（ZIP）”，把文件带到新电脑。这是直接可解压的工程包，带有使用知识、开发交接说明和此版本源码；不包含手机当前目标草稿、大麦账号、实名、订单或运行授权。

1. 在电脑解压“票务助手-电脑交接-版本.zip”。只解压这一次，得到的就是工程根目录，可以看到 AGENTS.md 和 handoff/START_HERE.md。
2. 在 Codex 或其他开发助手中打开该工程，先读这两份接手文件，再读 README.md、VALIDATION.md。
3. 按 START_HERE 执行只读 doctor，先核对开发环境与证据。需要真机调试时，再连接和授权当前这台 vivo。
4. 根据实际日志修复、构建和测试；新的安装、页面操作或实单验证应按本次任务范围执行。

可以使用页面中的“复制给模型的接手说明”，附上交接包或源码目录。模型仍需要实际文件内容，只有这段说明或聊天截图并不能恢复整个工程。

## 资料包能带走什么

源码快照和知识用于延续开发，不会在手机里自动编译或执行。App 可离线检索说明、导出工程资料；编译安装包需要电脑上的 JDK 17、Android SDK 和 Gradle。

交接包不包括这些工具链、开发缓存、签名密钥或账号凭据。它也不会转移无障碍权限、Shizuku 授权、正在执行的动作或下单许可。

资料随安装包更新。换电脑后继续使用的是该版本的工程证据，不能把历史测试中的设备状态、库存或演出授权当成当前事实。导出到公共位置后，由你决定保存和分享范围。

## 配置恢复只是备用工具

备用的资料备份包与主入口的电脑工程包不同：备份包可以带公开目标草稿，解压后先读外层 HANDOFF.md；如果要取其中源码，再解压 handoff/source.zip。主入口“导出电脑交接包（ZIP）”无需这一步。

如果以后重装应用、需要恢复公开目标，在“配置与资料备份（可选）”点击“选择备份并预览”，先预览再保存。导入完成后任务保持暂停，导入的目标只是草稿，必须从真实大麦重新选择项目、场次与票价后才能开始。

换电脑继续开发不需要这一步。导入不会恢复大麦登录、系统权限、观演人资料或订单，也不会清除本机已有提交记录。存在结果不明的订单时，先到官方大麦核查，避免重复下单。
