# 权限、连接和手机重启

## 界面读取：只开启这一项

在手机的无障碍设置中，找到“已下载的服务”或“已安装的应用”，进入“票务助手 · 界面读取”，打开页面顶部的服务开关，并确认系统提示。

不用开启 TalkBack，也不用开启“快捷方式”。如果开启 TalkBack 后手机变成点一次选中、点两次执行，那是屏幕朗读操作方式，并不是票务助手需要的设置。

手机品牌和系统版本不同，菜单名称可能变化；以包含“票务助手 · 界面读取”的服务为准。系统授权需要你在手机上确认。

## 通知：告诉你何时需要接手

允许票务助手发送通知。还需要检查手机是否开启勿扰、静音，或单独关闭了应用的通知类别。允许通知不代表已经验证响铃和振动。

普通通知正文通常打开助手。通知中的“开始监控”才是启动动作；新版本优先使用助手首页的明确开始入口。

## 两种点击方式

无障碍触控使用系统提供的辅助功能。它是默认方式，但在此前测试的 vivo 上，部分大麦票档点击没有产生实际选择效果。

Shizuku 是可选的本机调试输入方式。它通过用户授予的本机权限执行普通点击。此前在 USB 连接的测试 vivo 上，这条路径已完成选票并进入确认购买页；其他手机仍须验证。

## Shizuku 的三个不同状态

1. 已启动：在官方 Shizuku 应用里启动服务，按应用给出的指引操作。
2. 已授权：在票务助手请求权限后，在 Shizuku 系统弹窗中允许票务助手使用。
3. 已连接：回到票务助手，点击连接，看到输入已连接。

只安装 Shizuku 不够，只允许权限也不等于已连接。手机重启后需要重新启动 Shizuku。连接恢复不会自动开始监控。

不要把“USB 连接方式”的“管理文件”“连接办公套件”当成 USB 调试开关。电脑联调时，USB 调试在手机开发者选项中；授权弹窗会提到允许这台电脑调试。

## 不连接电脑时，如何启动 Shizuku

Shizuku 官方支持在 Android 11 及以上通过无线调试启动。手机重启后，需再次启动服务；配对和启动是两个步骤。

在手机按 Shizuku 的“通过无线调试启动”指引操作：首次从 Shizuku 发起配对，在系统无线调试中取得配对码，按 Shizuku 提示完成配对，然后回到 Shizuku 启动。配对码只在手机正常界面填写，不发给聊天或写进日志。

服务运行后，再回助手点击“② 允许票务助手使用”和“③ 连接点击服务”。这些是官方支持的普通调试授权流程，不需要 root。菜单不可用或服务没有启动时，先处理手机提示，助手保持暂停。

参考：[Shizuku 官方用户手册](https://shizuku.rikka.app/zh-hans/guide/setup/)。官方支持这种启动方式，不等于票务助手在本台 vivo 的物理拔线流程已经通过；该项仍待完整验收。

## 什么时候才需要接电脑

平时的目标选择、开始、暂停和查看指南在手机完成。电脑用于开发、安装更新和定位问题。换一台开发电脑时，手机上的设置不用重建；如果需要连接调试，按手机系统提示允许那台电脑即可。

只有重装应用或另外恢复配置时，才需要重新检查相应权限。导出的交接包不携带系统授权或大麦登录，也不会代替手机上的确认。

## 可选 AI 的接口与密钥

在任务或设置中打开“AI 辅助”，展开模型设置。填写服务商给出的 HTTPS 地址、模型名和 API Key；功能默认关闭。密钥仅在手机输入，不发到聊天，也不写入问题、笔记或演出配置。保存后不显示原文，可以主动清除。

密钥与接口配置使用 Android Keystore 加密，保存在不参与备份的本地文件。更换接收地址时需重新核对密钥，不应把一个服务的密钥发给另一个地址。程序保留普通 HTTPS 证书验证并拒绝重定向，不提供忽略证书选项。

连接测试会发出一次最小请求，不附带页面摘要，也计入每日次数。每次正式分析都先展示将发送的问题、摘要和接收方，由你确认。日常轮询和离线指南不使用模型；开启网络权限不表示已经开启自动上传。
