# TicketPilot v0.1.14 交互动线与验收

## 产品目标

用户打开应用即可看懂想买哪一场、接受哪些票价、程序现在做什么，以及下一步该点哪里。普通使用不要求理解无障碍树、输入后端、请求上下文或配置草稿等实现术语。相关信息不足时说明缺什么；没有真实订单时不能用成功样式表示锁票。

参考正规票务应用的基本购票顺序：搜索演出、确认地点和日期、按价格选择、核对金额与订单。依据为 [Ticketmaster 官方应用指南](https://help.ticketmaster.com/hc/en-us/articles/22926422411537-How-do-I-use-the-Ticketmaster-App) 与 [大麦如何购票](https://help.damai.cn/helpPage.htm?pageId=18)。本次只借鉴用户动线，不声称具备其他产品的速度或成功率。

## 三条日常路径

1. **第一次使用**：抢票页的主要按钮 → 准备好手机 → 从真实大麦选择演出 → 选场次 → 多选接受票价 → 核对并保存 → 设定有票后的动作 → 开始。
2. **再次运行**：首页直接确认演出票卡 → 如有需要点“有票后”或“检查速度”修改 → 开始 → 等待切回大麦 → 实际检查页面。切回助手、锁屏或异常后的处理以真实运行状态为准，不自动恢复。
3. **需要帮助**：在需求、场次、票价、速度或暂停位置点对应 AI 帮助 → 相关问题与公开参考在本机自动带入 → 查看接收方并点发送 → 阅读建议 → 返回原步骤或核对计划。回复不直接执行点击或创建订单。需要补充偏好时可继续追问，带入上一轮公开交流；“开始新问题”清除追问语境。

## 页面职责

| 位置 | 用户要解决的问题 | 主要操作 |
| --- | --- | --- |
| 抢票 | 我想买什么，现在到哪一步了？ | 固定底部的选择、准备、开始或暂停 |
| 演出选择 | 哪个城市、哪天、哪些票价？ | 每一步一个继续按钮，卡片选择，最后页内核对 |
| 有票后 | 程序继续到哪里？ | 提醒、选票到确认页；锁票能力未完成时明确不可用 |
| 检查速度 | 想快一点还是少操作？ | 三个预设、自定义区间，独立保存或取消 |
| 场景 AI | 这一步怎么选、为什么停下？ | 预填问题、一次发送、回复置顶、返回当前选择 |
| 我的 | 如何管理 AI、手机准备与维护？ | 模型管理、手机准备、更多设置、帮助与记录 |

权限和连接只展示当前需要处理的事项。外部设置启动后关闭旧弹层，返回首页重新读取状态。高级手动表单仍可用，但不再是日常操作主路径。

## AI 如何融入

没有通用主题选择器作为必经步骤。入口根据当前任务提供用途与问题；实际参考信息沿用经过筛选的本机目标、近期目录、有限页面摘要和用户保存的笔记。当前节奏与通用连接状态作为可见参考加入；打开 AI 前的暂停原因只投影为固定类别，不传原始状态文本。

本地自动整理不会发起网络请求，也不会自动读取新画面。接收方与摘要常驻显示，完整正文及系统说明在同页展开；点击“发送给 AI”后使用同一份冻结内容和模型参数。换地址、改问题、切后台或取消会使旧请求状态失效。需读取新的大麦页面时，由用户明确点击更新。

普通库存轮询继续用手机规则。AI 辅助不增加逐轮网络时延，不代替真实日期、价格、库存与订单验证。追问只保留在本次页面的内存中；长篇历史采用有明确省略提示的首尾节选，本次问题不截短。付款始终由用户完成，自动锁票仍需真实生产适配。

## 必须分别验收

代码、单元测试、构建与真机界面是不同证据。当前真机离线，下列实际交互尚未完成：

- 空目标时可以保存速度和模式，但不能因此启动；取消单项弹层不留下临时值。
- 演出票卡在常用字体和系统大字体下可读；日期包含年份；底部主要按钮不会被内容或键盘遮挡。
- 用户未切回大麦时显示等待与剩余时间，不能提前写成已查到库存。
- 项目、日期与票价的选择和返回清楚；AI 返回不丢尚未保存的选择。
- 修改搜索词后 AI 使用新问题；补充回答保留必要语境，新问题不会带入旧问答。
- 模型设置与主流程隔离；升级保留已保存接口、密钥、额度与订单防重记录。
- 请求预览、发送、取消、后台返回、超时、失败和大回复均有清楚状态，不自动重复请求。
- 对旧弹层、目录修订、配置变化和暂停后的再次开始重新核验；不会从历史草稿恢复下单授权。
- 自动锁票选项保持真实能力状态；本次不以界面展示代替真实待付款订单证据。

本次测试与设备状态以 `VALIDATION.md` 最新记录为准。
