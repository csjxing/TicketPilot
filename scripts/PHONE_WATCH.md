# vivo 现场监控

> 历史电脑端工具：代码仍包含 2026-10-11 孙燕姿杭州场次、固定分辨率及本机工具路径，不是当前通用入口，不能直接沿用旧配置启动。当前手机 App 见 [TicketPilot](../README.md)；本目录不是 Android App 的运行依赖。以下记录仅描述当时实现与验收边界。

这是独立的真实手机 UI 入口，不改变 `python3 -m damai` 的离线演练模式。读取本地 `watch.json`，通过已授权 ADB 标准点击、截图、控件树和 macOS Vision OCR 工作。没有大麦私有 API、验证码处理、付款操作或日常 LLM 轮询。

```
swiftc scripts/phone_ocr.swift -o .runtime/live/phone-ocr-v2
cp .runtime/live/phone-ocr-v2 .runtime/live/phone-ocr
python3 scripts/phone_control.py start
python3 scripts/phone_control.py status
python3 scripts/phone_control.py stop
```

需要已连接的授权 vivo V2547A、1260×2772 屏幕、前台大麦目标票档页和现有登录。配置含姓名，仅在被忽略的本地文件保存。截图、模型诊断和订单提交防重记录也仅在 `.runtime/live/`，不要提交或公开。

前三轮缺货按约 4 秒一轮，之后至第 12 轮约 5 秒，持续稳定后 6 秒，每轮在基础间隔上随机浮动 ±20%。实际间隔受界面读取耗时影响。缺货时每轮返回详情再进入票档页，降低缓存风险（未验证每次重入均请求服务器）；不提交缺货登记。任何可选信号立即进入订单核验。到本地配置截止时间退出。

提交前要求项目、日期时间、票价、数量、已选观演人、总价和额外付费项目检查通过。先持久化 `submission.json` 再点击一次立即提交；结果不明也保留防重记录，禁止自动删除重试。订单结果和付款期限以手机官方页面为准。

阻塞时可调用一次 `gpt-6-luna` low 进行截图诊断，CLI 使用只读权限，提示不使用工具，返回受限动作。Python 对结果再次核对并执行白名单动作，未确认字段不执行。单进程最多三次诊断，连续恢复失败直接停止。断连、离开大麦、验证码、网络故障等不能取得可靠画面时直接要求用户处理。模型不可用也停止并发 Mac 通知及提示音。模型调用并非承诺免费；常规轮询不调用模型。

现场已验证：本机 OCR、目标日期和票档识别、缺货分类、票档切换和退出再进入读取；低消耗模型文本及截图结构化输出可用。当前没有真实可售目标票，因此完整的真实下单和待付款流程尚未端到端验收，不保证抢到或提交成功。保持手机连接且处于该页面；用户开始操作、登录或支付时应停止脚本。

常见运行状态：`out_of_stock` 正常缺货、`stock_signal` 核验中、`model_recovery` 模型诊断、`needs_user` 已停止需用户操作、`pending_payment` 待付款、`submission_result_unknown` 需人工核实且不重试、`expired` 截止退出。通知是本机 Mac 通知，不是聊天消息或手机推送。

明确读到目标日期且三个目标票档各自带缺货标签时，仅用截图 OCR 判断缺货，省去控件树抓取。有任何缺失或可能有票时仍读取完整控件树并执行全部订单检查。

OCR 通过常驻本机进程处理最新截图，带 5 秒响应上限和单次识别回退。状态文件记录每轮实际处理时长和最近 OCR 时长；这不包含下一轮等待时间。正常轮询仍无模型调用。

每轮结果追加保存到 `.runtime/live/poll-history.jsonl`，不覆盖历史。包含 UTC 时间、运行 ID、轮次、事件序号、票档信号、耗时和异常原因；异常库存标为 unknown，不记为缺货。有票信号在点击前落盘。订单及恢复等状态也记录为 lifecycle 事件。旧版本仅保存最新状态，启动记录前的历史无法补回。
